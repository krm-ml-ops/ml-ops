# Методические указания для преподавателей по ресурсам

## Общие требования к условиям реализации лабораторного практикума

Учебная среда по дисциплине `Основы MLOps` должна обеспечивать выполнение лабораторных работ по контейнеризации, CI/CD, построению ML-пайплайнов, управлению экспериментами и версиями данных, развертыванию сервисов и мониторингу ML-систем.

Среда должна поддерживать:

- сборку и запуск контейнеров;
- локальный запуск Python-приложений и API-сервисов;
- выполнение базовых сценариев CI/CD;
- локальный или имитируемый мониторинг сервисных и модельных метрик;
- хранение и проверку артефактов, данных, моделей и конфигураций.

При отсутствии облачной инфраструктуры все лабораторные работы должны оставаться выполнимыми на локальной рабочей станции или в локально развернутой учебной инфраструктуре.

## Рекомендуемый стек программного обеспечения

Для проведения лабораторных работ рекомендуется использовать следующий стек программного обеспечения:

- ОС Linux либо Windows 10/11 с использованием WSL2;
- Python 3.10 или новее;
- Git;
- Docker Engine или Docker Desktop;
- Docker Compose;
- GitHub Actions или Jenkins для реализации учебных сценариев CI/CD;
- FastAPI;
- MLflow;
- DVC;
- Prometheus;
- Grafana.

В зависимости от содержания конкретной лабораторной работы дополнительно могут использоваться:

- `scikit-learn`;
- `pandas`;
- `numpy`;
- `PyYAML`;
- `prometheus-client`;
- иные Python-библиотеки, прямо указанные в вариантах лабораторных заданий.

## Платформенные замечания

- Linux следует рассматривать как эталонную среду выполнения.
- При работе в Windows рекомендуется использовать WSL2 для минимизации различий в командах, файловых правах и поведении контейнерного окружения.
- Особенности прав Docker, поведения смонтированных томов и различий между bind mount и volume целесообразно разъяснить до начала лабораторных работ по контейнеризации.
- Локальный registry контейнеров, MLflow Tracking Server и удаленное DVC-хранилище допускается моделировать через локальные каталоги, сервисы и контейнеры.

## Методические ориентиры по лабораторным работам

### Лабораторные работы 01-02

Следует обеспечить доступность Docker, Docker Compose, Python и Git, а также возможность сборки образов, запуска контейнеров, монтирования каталогов и сохранения артефактов во внешние директории.

### Лабораторная работа 03

Следует обеспечить возможность демонстрации сценариев CI/CD на базе GitHub Actions либо Jenkins, включая запуск тестов, статических проверок, сборку Docker-образа и сохранение артефактов pipeline.

### Лабораторная работа 04

Следует обеспечить доступность библиотек для построения ML-пайплайнов и конфигурационного управления, включая `scikit-learn`, `pandas` и `PyYAML`, а также возможность сохранения модели, метрик и конфигурации.

### Лабораторная работа 05

Следует обеспечить возможность запуска локального MLflow Tracking Server с backend store и artifact store, а также регистрацию параметров, метрик, артефактов и версий моделей.

### Лабораторная работа 06

Следует обеспечить работу DVC совместно с Git, включая локальный кэш, удаленное хранилище, `dvc.yaml`, `dvc.lock`, команды `push`, `pull`, `repro` и сравнение состояний pipeline.

### Лабораторная работа 07

Следует обеспечить возможность локального запуска FastAPI-сервиса модели, проверки HTTP-интерфейса, обработки ошибок и контейнеризации API-приложения.

### Лабораторная работа 08

Следует обеспечить доступность Prometheus, Grafana, Docker Compose и `prometheus-client`, а также возможность настройки сбора метрик, подготовки dashboard и контроля сервисных, инфраструктурных и модельных показателей.

## Подход к обеспечению дисциплины

Предпочтительно использовать небольшие открытые датасеты, синтетические учебные данные и легковесную локальную инфраструктуру. Методическая цель дисциплины состоит в формировании инженерной культуры разработки, развертывания, сопровождения и мониторинга ML-решений, а не в развертывании крупномасштабной промышленной платформы.
