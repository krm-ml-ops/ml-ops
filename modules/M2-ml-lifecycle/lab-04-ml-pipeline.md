# Лабораторная работа 04. Простая реализация ML pipeline

## Цель работы

Реализовать воспроизводимый ML pipeline от загрузки данных до сохранения модели с явной валидацией, конфигурацией и метриками.

## Задачи работы

1. Разделить workflow на понятные этапы обработки.
2. Отделить конфигурацию от кода.
3. Валидировать входные данные перед обучением.
4. Исключить утечку данных на этапе preprocessing.
5. Сохранять модель, конфигурацию и метрики оценки.

## Необходимое программное обеспечение

- Linux или Windows 10/11 с WSL2
- Python 3.10+
- Git
- Docker Engine или Docker Desktop
- scikit-learn
- pandas
- PyYAML или инструменты конфигурации на основе JSON

## Краткие теоретические сведения

ML pipeline формализует последовательность шагов от сырых данных до оцененных модельных артефактов. Явные границы этапов упрощают отладку, воспроизводимость и последующую автоматизацию. Управление выполнением через конфигурацию является основой надежного управления экспериментами и жизненным циклом. В рамках работы преподаватель может намеренно внести в открытый набор данных пропуски, выбросы, дублирующиеся записи и некорректные значения; до обучения необходимо проанализировать качество данных и подготовить очищенный набор.

## Задание

- Выполнить анализ качества исходного набора данных: выявить пропуски, выбросы, дублирующиеся записи и некорректные значения, подготовить их описание.
- Реализовать отдельный этап `prepare` для очистки данных, обработки пропусков, устранения или обработки выбросов, приведения типов и сохранения подготовленного набора.
- Обеспечить возможность повторного запуска этапа `prepare` без изменения остальных компонентов pipeline при неизменности исходных данных.
- Реализовать этапы `load`, `validate`, `split`, `preprocess`, `train`, `evaluate` и `save`.
- Хранить параметры в YAML или JSON.
- Сформировать журнал выполнения с длительностью этапов.
- Проверять схему данных, пропуски и допустимые диапазоны.
- Использовать `sklearn.pipeline.Pipeline` или эквивалентную функциональную схему.
- Сохранять обученную модель, метрики, конфигурацию и сведения о версии данных.
- Реализовать повторный запуск одной командой.
- Добавить минимум два автоматических теста: на валидацию данных и на форму результата pipeline.

## Минимальный порог

5 баллов.

## Типовые ошибки

1. Утечка данных (препроцессор обучен на всей выборке).
2. Нет обработки пропусков и выбросов в этапе prepare.
3. Нет валидации данных на этапе validate.
4. Параметры захардкожены в коде.
5. Нет журнала выполнения.
6. Нет тестов.
7. Нет сохранения версии данных.

## Правила защиты

1. Демонстрация работы — не более 10 минут.
2. Студент запускает pipeline одной командой, показывает сохраненные модель, метрики, конфиг и логи этапов.
3. Студент отвечает минимум на 5 контрольных вопросов из 10 по выбору преподавателя.
