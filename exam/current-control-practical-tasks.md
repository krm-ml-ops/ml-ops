# Практические задания текущего контроля

Источник: приложение № 3 файла [`ФОС-1.2.0.md`](../sources/fos/md/ФОС-1.2.0.md).

## Практические задания и задачи к текущему контролю

1. Составьте структуру репозитория для небольшого ML-проекта, включив каталоги для данных, кода, тестов, конфигураций, моделей и CI/CD.
2. Напишите минимальный `Dockerfile` для FastAPI-сервиса, который устанавливает зависимости и запускает приложение через `uvicorn`.
3. Предложите набор шагов GitHub Actions для проверки качества кода, запуска тестов и сборки Docker-образа.
4. Опишите, какие параметры, метрики и артефакты следует логировать в MLflow для задачи классификации.
5. Составьте последовательность команд DVC для добавления датасета, настройки `remote` вне репозитория, фиксации метаданных в Git, `push` и восстановления на другой машине через `pull`.
6. Разработайте схему REST API для модели: endpoint, формат входных данных, формат ответа и обработка ошибок.
7. Определите набор продуктовых, модельных и инфраструктурных метрик для сервиса прогнозирования оттока клиентов.
8. Предложите алгоритм действий при обнаружении data drift без немедленного падения целевой метрики.
9. Составьте план A/B-теста новой версии модели и укажите критерии остановки эксперимента.
10. Опишите меры защиты логов и данных запросов, содержащих персональную информацию.
11. Для бинарной классификации с долей положительного класса 5% выберите стратегию валидации и минимум две метрики качества. Объясните, почему одной `accuracy` недостаточно, и как сравнить две модели.
12. Обоснуйте выбор Docker и DVC для контейнеризированного ML-проекта: укажите, какие артефакты и метаданные хранятся в Git и DVC, как контролируется доступ к `remote` и как восстанавливается ревизия данных.
